# BFE-001: Missing recommended security headers

| Field | Value |
|---|---|
| Rule ID | `BFE-001` |
| Proposed rule version | `1.0.0` |
| Default severity | `medium` (registry value, BLUEPRINT §8; a default, not a risk judgment) |
| Target release | v0.1 |
| Status of this page | Implemented in WO-003 (rule version 1.0.0). Implementation: `packages/core/src/rules/bfe-001-security-headers.ts`; input schema: `bfe-001-input.ts`; tests: `packages/core/tests/rules/bfe-001.test.ts`; fixtures: `tests/fixtures/rules/bfe-001/`. |

## 1. Concern

Browsers apply many protections only when the server opts in through response headers. When an HTML-serving Express app omits them, clickjacking (no framing restriction), MIME-sniffing of uploads or user content (no `X-Content-Type-Options`), weaker cross-site scripting mitigation (no `Content-Security-Policy`), first-visit downgrade or stripping on HTTPS sites (no `Strict-Transport-Security`) and information leakage (`X-Powered-By`, permissive `Referrer-Policy`) all become easier. Express sends `X-Powered-By: Express` by default and sets none of the others. The risk is easy to misjudge in both directions. Teams assume a proxy or CDN adds the headers when it does not, and scanners flag apps whose headers are set by Nginx, a CDN or a per-route middleware they cannot see. This rule reports what the declared evidence shows, and says `not_assessed` when it cannot see the layer that decides. A passing result does not mean the app is secure. It means the checked headers were observed with acceptable values in the evidence supplied.

## 2. Inputs & evidence

The rule is a pure function of one typed input. Collectors (scanner, config loader, optional sample loader) build it. The rule performs no I/O, and it never reads the clock, the environment or the network.

### 2.1 Proposed input type

```ts
export type Tri = "yes" | "no" | "unknown";

export interface SecurityHeadersInput {
  app: {
    kind: "html" | "api" | "mixed" | "unknown";   // declared in config; default "unknown"
    expressAppFound: boolean;                     // an Express app identifier was resolved
  };
  transport: {
    // Where TLS terminates, as DECLARED. "none" = declared plain-HTTP only (local/dev).
    https: "app" | "proxy" | "none" | "unknown";
  };
  proxy: {
    present: Tri;                                 // reverse proxy / CDN in front, as declared
    headerConfig: "supplied" | "not_supplied";    // header directives supplied for it
  };
  coverage: {
    complete: boolean;                            // false if any limit hit / file skipped / unparsed
    limitsHit: string[];                          // e.g. "max-files", "parse-error:src/app.ts"
    unresolvedMiddleware: boolean;                // app built dynamically or aliases unresolved
  };
  settings: {
    poweredBy: "disabled" | "enabled" | "unknown"; // app.disable("x-powered-by") seen / not seen
  };
  helmet: {
    dependency: "present" | "absent" | "unknown";  // package.json hint only
    version?: string;                              // declared range, e.g. "^8.0.0"
    mounts: HelmetMount[];
  };
  headers: HeaderObservation[];                    // everything else (see 2.2)
  sample?: {                                       // present only if a sample was supplied
    capturedAt: "edge" | "origin" | "unknown";     // edge = through proxy/CDN
    scheme: "https" | "http" | "unknown";
    route: string;                                 // path only, no query string
    isHtml: Tri;
  };
}

export interface HelmetMount {
  scope: "global" | "route" | "conditional" | "unresolved"; // conditional = inside if/env check
  location: string;                                          // POSIX-relative "file:line"
  // Per header option state; keys are lower-case header names. Absent key = "default".
  options: "default" | "unresolved" | Record<string, { state: "default" | "disabled" | "custom"; value?: string }>;
}

export interface HeaderObservation {
  name: string;                         // lower-case; allowlisted names only (see 2.3)
  state: "set" | "removed" | "absent";  // "absent" is valid only for layer "sample"
  value?: string;                       // omitted when not a literal
  layer: "app" | "proxy" | "sample";
  scope: "global" | "route" | "unknown";
  origin: "source" | "declared" | "parsed-proxy-config" | "sample";
  location?: string;
  route?: string;
}
```

Collectors fill `headers` from literal `res.setHeader`, `res.set` and `res.header` calls in middleware (global or route), from the user's declared `deployment` block (`origin: "declared"`), from an optional parsed proxy file, and from a user-supplied response-header sample. The sample is a file the user captured. The rule never fetches anything.

### 2.2 Evidence ranking and base confidence

| Source | Meaning | Ceiling |
|---|---|---|
| Sample captured at `edge`, route is HTML | What the browser got | high |
| Declared deployment config (user statement) | Proxy present or absent, TLS location, headers the proxy adds | high |
| Parsed proxy config file (specific directives only) | Proxy header directives | medium (inheritance and `always` rules make parsing partial) |
| Source AST, literal values | `helmet()` mount, `setHeader` calls | medium (order, conditionals and other modules are not fully visible) |
| `package.json` dependency hint | helmet listed | low (presence is not use) |

Spread-out setup (router factories, helmet in another module) lowers confidence one level, and the evidence text must say so (static-analysis-safety).

### 2.3 Allowlist and redaction

The rule reads only these header names: `content-security-policy`, `content-security-policy-report-only`, `strict-transport-security`, `x-content-type-options`, `x-frame-options`, `referrer-policy`, `cross-origin-opener-policy`, `cross-origin-resource-policy`, `permissions-policy`, `x-xss-protection`, `x-powered-by`. The collector drops every other header, including `set-cookie`, `authorization` and `cookie`, before building the input. Evidence strings contain header names, fixed verdict phrases, normalized numbers and a `file:line` location only when it matches `^[\w./-]+:\d+$` (anything else is dropped). Raw header values, routes and `limitsHit` text are never echoed (counts only). For CSP, evidence names directives and flagged keywords only, never full source lists or report URIs. Sample routes are logged without query strings.

### 2.4 Helmet expansion table (pinned, deterministic)

Verified against the helmet documentation at spec time (see References note). The rule expands a helmet mount as follows. When `version` is missing, unparsable or its major is not in the table, helmet is treated as "sets the headers, values unknown": presence checks give a low-confidence warning (never pass) and value checks are skipped. Never guess values.

| Header | Default value from `helmet()` (current major) | Disabled by option key |
|---|---|---|
| content-security-policy | helmet default policy (`default-src 'self'` plus restrictive directives, `upgrade-insecure-requests`) | `contentSecurityPolicy: false` |
| strict-transport-security | `max-age=31536000; includeSubDomains` | `strictTransportSecurity: false` |
| x-content-type-options | `nosniff` | `xContentTypeOptions: false` |
| x-frame-options | `SAMEORIGIN` | `xFrameOptions: false` |
| referrer-policy | `no-referrer` | `referrerPolicy: false` |
| cross-origin-opener-policy | `same-origin` | `crossOriginOpenerPolicy: false` |
| cross-origin-resource-policy | `same-origin` | `crossOriginResourcePolicy: false` |
| x-xss-protection | `0` | `xXssProtection: false` (header then omitted, which is acceptable) |
| x-powered-by | removed | `hidePoweredBy: false` |

Helmet does not set `Permissions-Policy` or `Cross-Origin-Embedder-Policy` by default. Mounts with `scope: "global"` contribute global observations with `origin: "source"`. `route` mounts contribute `scope: "route"`. `conditional` and `unresolved` mounts contribute nothing and force affected headers to `unknown` (not assessed), because the condition may hold in production.

## 3. Decision table

### 3.1 Headers checked and tier

"Applies to" uses `app.kind`. `unknown` is treated like `html` for applicability, but absence can then only reach `warning` (row D9), never `fail`, for headers marked "html-only".

| # | Header | Applies to | Tier | Acceptable value (pass) | Value problem (warning) |
|---|---|---|---|---|---|
| H1 | `X-Content-Type-Options` | all | A (fail-eligible) | `nosniff` (case-insensitive, trimmed) | Any other value is invalid and has no effect, so treat as absent (fail) |
| H2 | Framing protection: `X-Frame-Options` or CSP `frame-ancestors` | html, mixed | A, html-only | XFO `DENY` or `SAMEORIGIN`, or CSP `frame-ancestors` with `'none'`, `'self'` or an explicit origin list | `frame-ancestors *`, or XFO `ALLOW-FROM` only (ignored by browsers, so treated as absent: fail) |
| H3 | `Content-Security-Policy` (enforcing) | html, mixed | A, html-only | Present and enforcing | Only `-Report-Only` present (warning). Weak `script-src` (or `default-src` fallback): `'unsafe-inline'` without nonce/hash/`'strict-dynamic'`, `'unsafe-eval'`, bare `*`, `data:` or `http:` sources (warning) |
| H4 | `Strict-Transport-Security` | all, only when HTTPS is established (D4) | A | `max-age` >= 31536000 | `max-age` 1..31535999 or `max-age=0` (warning). `includeSubDomains` and `preload` are NOT required (they can break subdomains and `preload` is hard to undo) |
| H5 | `Referrer-Policy` | html, mixed | B (warning-only) | `no-referrer`, `same-origin`, `strict-origin`, `strict-origin-when-cross-origin`, `origin`, `origin-when-cross-origin` | `unsafe-url`, `no-referrer-when-downgrade`, empty or unrecognized. Absent is a warning, because browsers already default to `strict-origin-when-cross-origin` (MDN) |
| H6 | `Cross-Origin-Opener-Policy` | html, mixed | B | any value except `unsafe-none` | absent, or `unsafe-none` |
| H7 | `Cross-Origin-Resource-Policy` | html, mixed | B | `same-origin`, `same-site` or `cross-origin` (explicit choice) | absent |
| H8 | `X-Powered-By` | all | B | Removed (`app.disable("x-powered-by")`, helmet, or sample lacks it) | Enabled or present in sample |
| H9 | `X-XSS-Protection` | all | B | Absent or `0` | Any value starting with `1` (obsolete and can introduce issues; MDN, OWASP) |
| H10 | `Permissions-Policy` | html, mixed | Advisory | n/a | Never changes status. Listed in evidence as an "advisory: not set" line only |

Not checked in v0.1: `Cross-Origin-Embedder-Policy` (breaks cross-origin embeds; needed only for cross-origin isolation), `Origin-Agent-Cluster`, `X-DNS-Prefetch-Control`, `X-Download-Options`, `X-Permitted-Cross-Domain-Policies`, `Cache-Control`. For `app.kind: "api"`, only H1, H4, H8 and H9 apply. H2 to H3, H5 to H7 and H10 are skipped with an evidence line "not evaluated: declared API-only".

### 3.2 Per-header effective state

Evaluate in order for each applicable header `h`. The first matching row wins.

| # | Condition | Per-header state | Confidence |
|---|---|---|---|
| D1 | Sample present, `capturedAt` is `edge`, `isHtml` is yes (or `app.kind` is `api` and header applies), header observed with an acceptable value. For H4 the sample scheme must be `https`. | pass | high |
| D2 | Any global observation (app or proxy layer) `set` with an acceptable literal value, and no global `removed` for it | pass | medium for source, high for declared or edge sample |
| D3 | Observed `set` with a non-literal value (variable, `process.env`) or a helmet mount with unknown version | warning (never pass: the value cannot be verified; CLAUDE.md 1.4); value checks skipped; evidence says the value is not a literal | low |
| D4 | HSTS only: `transport.https` is `none` (declared plain HTTP) | H4 skipped, evidence "HTTP-only deployment declared" | n/a |
| D4b | HSTS only: `transport.https` is `unknown`, or the sample scheme is `http` or `unknown` | not_assessed for H4 (HSTS is ignored over HTTP, MDN) | n/a |
| D5 | Observed `set` with a value in the "value problem" column | warning (exception: H1 invalid value, H2 `ALLOW-FROM` only: fail) | medium |
| D6 | Observation exists only with `scope: "route"` or `"unknown"` (per-route middleware, helmet on a sub-router, mount after routes) | warning, evidence lists routes and says other routes are unseen | medium |
| D7 | `coverage.complete` is false, or `coverage.unresolvedMiddleware` is true, or helmet mount is `conditional`/`unresolved`, or `expressAppFound` is false and no sample or proxy evidence exists | not_assessed | n/a |
| D8 | Header unseen AND `proxy.present` is `yes` AND `proxy.headerConfig` is `not_supplied` | not_assessed ("a proxy is declared and its header config was not supplied") | n/a |
| D8b | Header unseen AND `proxy.present` is `yes` AND header config supplied AND proxy layer does not set it AND coverage complete | absent-confirmed (D10) | medium |
| D9 | Header unseen AND `proxy.present` is `unknown` (nothing declared) | warning at low confidence: "not found in app code; a proxy or CDN not described to this tool may add it" | low |
| D10 | Header unseen AND (`proxy.present` is `no` declared, or sample at `edge`/at `origin` with proxy `no`, shows `absent`) AND coverage complete AND express app found, and no helmet `disabled` entries are the only reason | absent-confirmed: Tier A and applicable becomes fail; Tier B becomes warning. `app.kind: unknown` and html-only header: warning, never fail | high if from sample (D1 conditions), otherwise medium |
| D11 | Sample at `origin` shows header absent, `proxy.present` is `yes` or `unknown` | not_assessed for that header (the edge may add it); a sample at `origin` showing the header present still follows D1/D2 at medium | n/a |
| D12 | Sample at `unknown` capture point showing absent | same as D11 | n/a |
| D13 | `removed` declared in proxy layer for a header the app sets | treat as unseen at that layer, then re-evaluate from D10 | medium |

Where helmet is mounted with option `disabled` for header `h` and no other layer sets it, `h` is unseen. The evidence line says "disabled via helmet option" with its location, which may lift confidence to high only in D10 when a sample also shows absence.

### 3.3 Aggregation to a single RuleResult

The engine takes one `RuleResult` per rule, so the rule aggregates per-header states.

| # | Condition | Status | Severity | Confidence |
|---|---|---|---|---|
| A1 | No Express app found, no sample, no proxy header evidence (nothing to examine), or another framework detected (`@fastify/helmet`, `koa-helmet`, Next.js `headers()` etc.) | not_assessed | medium | low (evidence states what was missing) |
| A2 | At least one applicable header in `fail` | fail | medium | The lowest confidence among failing headers; never above medium unless every failing header came from an `edge` sample (high) |
| A3 | No `fail`, and at least one `warning` | warning | medium | The highest confidence among warning headers is NOT used; use the lowest, so a single low-confidence warning gives `low` |
| A4 | No `fail`/`warning`, and at least one applicable header is `not_assessed` | not_assessed | medium | low. Evidence lists every unresolved header and why |
| A5 | All applicable headers `pass` or were skipped by D4 or API scoping, and at least one header was assessed as pass | pass | medium | The lowest confidence among passing headers (so a helmet-only result reads medium, an edge sample reads high) |
| A6 | Mixed: some `fail` and some `not_assessed` | fail (A2), evidence lists the unresolved headers so the user does not read it as complete | medium | per A2 |

Hard constraints:

* No row anywhere returns `fail` when `proxy.present` is `yes` with `headerConfig: "not_supplied"` or `unknown`, unless the failing header is H1 or H2 invalid-value fail from a literal (D5), which is a value defect in a layer the rule did see.
* No row returns `pass` from an absence of evidence. `pass` always cites an observation (a sample, a literal setter, a declaration or a helmet mount).
* `pass` never states or implies "secure" or "compliant". Its description is "recommended headers were observed with acceptable values in the supplied evidence".
* `severity` is always the rule default `medium`; the engine contract has no per-status severity. See owner decisions in the hand-off.

## 4. False-positive traps

| Trap | Why it looks insecure | Required behavior |
|---|---|---|
| Nginx, Apache, Caddy, a CDN or an ingress adds headers | App code has no `setHeader` or helmet | D8/D9: `not_assessed` or low-confidence `warning`, never `fail`. If the user declares the headers the proxy adds, treat as set (declared, high) |
| Nginx `add_header` without `always` | Headers are only added to 2xx/3xx, so error pages lack them; an `add_header` in a `location` block drops those inherited from `server` | Parsed proxy config: confidence capped at medium and a note in evidence. Do not fail on it |
| Helmet mounted in another file, a router factory or `src/security.ts` | The main file shows nothing | Unresolved imports: D7 `not_assessed`. Resolved but spread: confidence one level lower |
| Helmet only in production (`if (process.env.NODE_ENV === "production")`) | Not visible as active | `conditional` mount: `not_assessed` for helmet-provided headers, no fail |
| Per-route or router-level middleware sets headers (e.g. CSP only on HTML routes, `nosniff` on `/uploads`) | Not global | D6 `warning` with route list, not fail |
| API-only app declares `app.kind: "api"` | No CSP, framing, referrer, COOP/CORP | Skipped, evidence line states so. H1, H4, H8 still apply. CSP on JSON is optional |
| `app.kind` not declared | Cannot tell HTML from API | html-only headers cap at `warning`, never `fail` (D10) |
| HSTS absent on an HTTP-only dev or internal service | HSTS is ignored over HTTP | `transport.https: none` skips H4; `unknown` gives not_assessed. A missing HSTS is never a fail without established HTTPS |
| TLS terminated at a proxy, app speaks HTTP | App never sends HSTS | HSTS can come from the proxy. Same proxy rows apply |
| `X-Frame-Options` absent but CSP `frame-ancestors` set | Classic header missing | H2 passes through either |
| `X-XSS-Protection` missing or `0` | Looks like a missing protection | Pass. It is obsolete; only a value starting with `1` is a warning |
| Helmet default `Referrer-Policy: no-referrer` or `X-Frame-Options: SAMEORIGIN` | Differs from OWASP's suggested `strict-origin-when-cross-origin` and `DENY` | Both are pass values |
| Explicit `cross-origin` CORP or `same-origin-allow-popups` COOP | Looks permissive | Deliberate choices for CDN assets and OAuth popups: pass |
| CSP with `'unsafe-inline'` in `style-src` only | Pattern match on `unsafe-inline` | Only `script-src` (or the `default-src` fallback when `script-src` is absent) is judged. Nonces, hashes and `'strict-dynamic'` neutralise `'unsafe-inline'` for scripts in modern browsers |
| Helmet pinned to a major not in the expansion table | Defaults unknown | Presence only, no value judgment |
| Sample captured at origin by curl on localhost | Missing proxy headers | D11/D12: `not_assessed` |
| Example config or test code (`*.test.ts`, `examples/`) with a bare `express()` | Not the deployed app | Collector skips test and example dirs by default; findings from them are not produced |

## 6. Remediation

The engine's `remediation` string should contain the neutral block first, then the Express block, with only the sections relevant to the failing headers.

### Framework-neutral (set at the app or at the proxy, but set them somewhere you control)

Add these response headers to HTML responses:

```http
Content-Security-Policy: default-src 'self'; object-src 'none'; base-uri 'self'; frame-ancestors 'self'; form-action 'self'
X-Content-Type-Options: nosniff
Referrer-Policy: strict-origin-when-cross-origin
Cross-Origin-Opener-Policy: same-origin
Cross-Origin-Resource-Policy: same-origin
Permissions-Policy: geolocation=(), camera=(), microphone=()
```

Over HTTPS only (it is ignored over HTTP):

```http
Strict-Transport-Security: max-age=31536000; includeSubDomains
```

Notes the remediation text must include:

* The CSP above is a starting baseline. Test it in `Content-Security-Policy-Report-Only` first, then tighten `script-src` with nonces or hashes instead of `'unsafe-inline'`.
* Raise HSTS `max-age` gradually. Add `includeSubDomains` only if every subdomain serves HTTPS. Do not add `preload` without reading the preload requirements; it is hard to reverse.
* Do not enable `X-XSS-Protection`; omit it or send `0`.
* JSON-only APIs need fewer headers: keep `X-Content-Type-Options: nosniff`, HSTS and no `X-Powered-By`; CSP, framing and `Referrer-Policy` mainly matter for responses a browser renders. Declare `app.kind: "api"` in the config to scope the rule.
* If a proxy or CDN already sets these, declare it in the `deployment` block (or supply the proxy config) so the next scan can see it.

### Nginx (when the proxy owns the headers)

```nginx
add_header X-Content-Type-Options "nosniff" always;
add_header Strict-Transport-Security "max-age=31536000; includeSubDomains" always;
add_header Referrer-Policy "strict-origin-when-cross-origin" always;
```

Repeat `add_header` lines inside any `location` block that defines its own `add_header`, because it replaces inherited ones. Use `always` so error responses carry them too.

### Express (helmet)

```js
import express from "express";
import helmet from "helmet";

const app = express();
app.disable("x-powered-by");   // helmet also removes it; explicit is clearer
app.use(helmet());             // mount before routes and static handlers

// Example: allow one trusted script origin and keep the rest of the defaults
app.use(
  helmet({
    contentSecurityPolicy: {
      directives: { "script-src": ["'self'", "https://cdn.example.com"] },
    },
  }),
);
```

For an API-only service, `app.use(helmet())` is sufficient; HTML-oriented headers are harmless on JSON. Behind a TLS-terminating proxy, also set `app.set("trust proxy", <exact hop count>)` so `req.secure` is correct (see BFE-006). The same code works on Express 4 and 5. Add `Permissions-Policy` manually, since helmet does not set it by default.

## 8. Limits

This rule cannot detect, and a pass does not imply anything about:

* What a deployed proxy, CDN, WAF or load balancer actually sends, unless the user supplies its header config or an edge sample. Its absence in supplied evidence is "unknown", not "none".
* Runtime behavior: headers set conditionally per request, per tenant, by feature flag, by `NODE_ENV` or by code in dependencies; middleware order across modules that were not resolved; headers removed later by `res.removeHeader`.
* Correctness of a CSP beyond a few keyword checks: it does not evaluate whether the policy blocks real injection, whether nonces are unique per response, or whether allowed hosts are trustworthy.
* Whether HTTP routes redirect to HTTPS, whether a domain is on a preload list, or whether TLS is configured safely (BFE-010, later).
* Non-Express servers and frameworks (Fastify, Koa, Next.js `headers()`), static hosting, serverless platforms: reported as not_assessed.
* Responses other than the one sampled: a sample is one route at one time.
* Header values that are computed at runtime (non-literal values give presence only).
* Anything about cookies, CORS or body limits (BFE-002, 003, 008).
* A header being present says nothing about vulnerabilities in the application itself. Headers reduce exposure to some browser-side attack classes; they do not remove the underlying defects.
